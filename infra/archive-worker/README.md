# Archive Worker

Read-only Cloudflare Worker in front of the `wb-archive` R2 bucket (EU jurisdiction).
It serves archived article records and the media they reference.
Only the `records/` and `media/` key prefixes are reachable; every other key returns 404.

## Endpoints

| Request | R2 key | Response |
| --- | --- | --- |
| `GET /records/{id}` | `records/{id}.json` | `application/json; charset=utf-8`. `id` must match `^[1-9]\d{0,8}$`, anything else is 404. |
| `GET /media/{path}` | `media/{decoded path}` | Image or PDF. Supports `Range`. |
| anything else | none | 404 |

- Methods: `GET` and `HEAD` only. Anything else is 405 with `Allow: GET, HEAD`.
- Hits: `Cache-Control: public, max-age=31536000, immutable`, `ETag`, `X-Content-Type-Options: nosniff`. `If-None-Match` returns 304.
- Misses: 404 with `Cache-Control: public, max-age=60`.
- Media paths are percent-decoded per segment and NFC-normalised to form the key. Empty or dot segments, encoded `/` or `\`, control characters and malformed encoding return 400.
- Media content type comes from the object's upload metadata, else from the extension (jpg, jpeg, png, gif, webp, svg, pdf). Any other type is served as `application/octet-stream` with `Content-Disposition: attachment`, so nothing renders as a page. SVG is also sent with `Content-Disposition: attachment`; `<img>` tags ignore it.

## Run locally

From the repo root:

```
pnpm install
pnpm --filter @wb/archive-worker seed:local -- --records <records dir> --media <media dir>
pnpm --filter @wb/archive-worker dev     # http://localhost:8787
```

`seed:local` defaults to `~/wb-archive-data/records-v8` and `~/wb-archive-data/media`.
It writes into the local R2 emulation under `.wrangler/state/v3`, the same store `wrangler dev` reads:

- every `<records>/{id}.json` (files starting with `_` are skipped) as `records/{id}.json`;
- every path listed in `<records>/_media.json`, read from `<media>/<path>`, as `media/<path>`;
- `meta/manifest.json`, mapping each record id to the sha256 of its file.

Re-running overwrites, so it is safe to repeat. The full export (about 115k objects) takes about four minutes.

The script starts a local-only loader Worker (`scripts/seed-worker.js`, `scripts/seed.wrangler.jsonc`) with `wrangler dev` on port 8797 and posts objects to it in batches.
`getPlatformProxy` was the first choice, but it opens one loopback connection per object and stalls on macOS after a few thousand.
The loader never runs outside `seed:local`; do not deploy it.
Occasional "Network connection lost" lines during a run are retried batches.
Nothing in this package talks to a Cloudflare account; `dev` runs with `--local`.

Example requests:

```
curl -i http://localhost:8787/records/186216
curl -I http://localhost:8787/media/app/za/GENERAL/Globe%20300x288.jpg
```

## Types

`worker-configuration.d.ts` is generated by `pnpm --filter @wb/archive-worker types` (`wrangler types`).
Re-run it after changing `wrangler.jsonc` or `compatibility_date`.
`pnpm --filter @wb/archive-worker typecheck` checks the Worker.
The root app's `tsconfig.json` and ESLint config exclude `infra/`.
